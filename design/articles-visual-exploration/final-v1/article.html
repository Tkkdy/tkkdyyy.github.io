上下文正在成为个人 AI 的真正界面

August 5, 2026 12 min read 前沿科技

在探讨个人与计算设备的交互历史时，我们通常将目光聚焦于图形用户界面（GUI）的演进。从早期的命令行界面，到 Xerox PARC 奠定的视窗系统，再到触控和空间计算时代，界面的核心目标始终如一：降低人机沟通的认知门槛，使其更接近人类的物理直觉。

然而，大语言模型（LLM）的常态化应用正在悄然改变这一范式。我们发现，真正的智能体验并不完全来自于模型参数的绝对规模，而在于模型能够随时调用的上下文质量（Context Quality）。

“When you have to explain your background to a tool every single day, it is not an assistant; it is merely an advanced typewriter.”

1. 语境的持久化

当你每天面对一个新的对话窗口，需要重新解释你的项目背景、编码习惯或行文风格时，AI 充其量是一个高级打字机。但当它能够无缝读取你过去三个月的工作文档、代码库修改历史和思维碎片时，它才开始跨越“工具”的属性，成为个人能力的真正延伸。

图 1: 记忆流动的双向机制（Normal Width Media）

构建一个有效的个人上下文系统，通常需要以下几个层次的抽象，这也是当前端侧智能系统正在攻克的基础架构难题：

  1. 短期记忆 (Short-term context): 当前正在编辑的活动文档、剪贴板内容、终端历史以及最近 10 分钟的屏幕视觉流状态。
  2. 中期记忆 (Project context): 正在进行的特定项目仓库、需求列表、近期的讨论记录，通常限定在特定的工作空间内。
  3. 长期记忆 (Personal ontology): 个人的价值观偏好、历史归档数据、长期积累的知识图谱。

1.1 存储与检索的代码范式

要在系统中实现这种记忆的持久化，我们往往需要通过向量数据库（Vector DB）或本地图数据库来管理。以下是一段用于结构化存储 ContextBlock 接口的 TypeScript 示例：

import { embed } from '@local/embeddings';
import { VectorDB } from '@local/storage';

interface ContextBlock {
  id: string;
  content: string;
  sourceUri: string;
  timestamp: number;
  embedding?: number[];
  tags: string[];
}

export class ContextManager {
  private storage = new VectorDB('personal_ontology');

  /**
   * Retrieves context blocks relevant to the current query.
   */
  async retrieveRelevant(query: string, limit: number = 5): Promise<ContextBlock[]> {
    const queryVector = await embed(query);
    return this.storage.search(queryVector, limit);
  }
}

在设计并维护这样一套持久化的上下文系统时，我们必须遵循几个核心原则，以确保其不会随着时间推移而劣化为一座信息垃圾场：

  • 最小干预原则：系统应在后台静默收集必要状态，尽量减少要求用户主动打标签或分类的频率。
  • 定期衰减机制：并非所有记忆都具有永久价值。短期项目的上下文应当在项目归档后自动降级，释放当前注意力空间的权重。
  • 隐私与本地优先：涉及个人本体论的深层数据，必须建立在本地存储与端侧推断的基础上，边界不可妥协。

2. 空间破局：超越单线程流

随着处理能力的增强，视觉呈现也必须打破单列的文本流限制。空间计算环境允许我们将不同时间维度的上下文并排陈列。在宽屏或多屏环境下，图片的排版可以突破正文宽度的限制，形成更加舒展的视觉节奏。

图 2: 突破正文宽度的系统架构概念图（Wide Media, ~1000px）

对比传统的工具型软件，基于上下文的 AI 表现出了截然不同的特性，这种转变直接影响了软件的工程组织方式：

交互属性 传统 AI 工具 上下文感知助理 (Agent)
起始状态 每次都是“白板 (Blank slate)” 基于历史状态自然延续
输入阻力 高（需要编写大量 Prompt） 极低（短指令甚至眼神停留）
输出特征 通用、标准化、不具个人色彩 高度个性化、符合隐性规范

2.1 并置与对比的视觉呈现

在设计系统界面时，我们也面临着类似排版的挑战：如何优雅地并置不同类型的信息碎片？在实际的摄影整理和视觉建档中，两张不同纵横比的媒体通常能够通过并排展示来产生奇妙的化学反应。

图 3: 桌面端双列排版，移动端将自动上下堆叠（Two-up Media）

3. 结论：形式的退让

最终，系统设计的美学应当退居幕后，让内容和智能的流动成为主体。在这套原型的最终迭代中，我们排除了所有的框线、卡片堆叠与强烈的色彩块。正如我们在寻找与 AI 共生的状态——让技术感来自底层的精确秩序，让人文感来自不经意间的留白与痕迹。
