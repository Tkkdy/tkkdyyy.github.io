### 理解 TP、FP、FN，以及 Precision、Recall 和 F1

今天又补了一轮模型评估指标的基础知识。

基础概念：

- **TP（True Positive，真正例）**：模型预测某个答案是正确的，而且它确实是正确答案。
- **FP（False Positive，假正例）**：模型把错误的候选当成了正确答案，也就是多提取了。
- **FN（False Negative，假负例）**：某个答案本来是正确的，但模型没有提取出来，也就是漏提取了。
- **TN（True Negative，真负例）**：某个候选本来就不是答案，模型也正确地排除了它。

其中，True / False 表示判断是否正确，Positive / Negative 表示预测为正例还是负例。

在目前的 CCKS 元素级 Micro-F1 评估中，主要关注 TP、FP、FN，不需要计算 TN。

练习：

**标准答案：** 上海、广州、深圳、杭州

**模型输出：** 上海、广州、北京

- TP = 2：上海、广州，正确提取。
- FP = 1：北京，不在标准答案里，却被模型输出。
- FN = 2：深圳、杭州，本来应该被提取，却遗漏了。

**Precision（精确率）关注模型输出的答案有多少是正确的：**

`Precision = TP / (TP + FP) = 2 / 3 ≈ 66.7%`

模型总共输出了三个答案，其中两个正确，所以精确率是 66.7%。

**Recall（召回率）关注所有正确答案中有多少被模型找到了：**

`Recall = TP / (TP + FN) = 2 / 4 = 50%`

标准答案总共有四个，模型只找到了其中两个，所以召回率是 50%。

**F1 则是 Precision 和 Recall 的调和平均：**

`F1 = 2 × P × R / (P + R)`

也可以直接通过 TP、FP、FN 计算：

`F1 = 2TP / (2TP + FP + FN) = 4 / 7 ≈ 57.1%`

这里我又补充理解了一点：F1 并不是 Precision 和 Recall 的普通算术平均，而是**调和平均**。当其中一个指标明显偏低时，F1 也会受到较大影响。

- FP 多，说明模型容易误报，Precision 往往会降低。
- FN 多，说明模型漏掉了不少正确答案，Recall 往往会降低。
- 仅仅提高 Recall 不一定能提高 F1，因为可能同时引入更多 FP。
- 调整预测阈值可能改变 Precision 和 Recall 之间的平衡，但并没有让模型真正学会新的知识。

## RoBERTa BIO Span 

RoBERTa 是一种以编码为主的预训练语言模型。它接收文本，输出带有上下文信息的表示

要抽取哪些答案、输出什么格式，需要具体任务的预测头和解码方式。

BIO 和 Span Extraction 则是在讨论**怎样表示或预测答案的位置**。

- **BIO**：给文本中的每个 token 打标签。`B` 表示一个片段的开始，`I` 表示片段内部，`O` 表示不属于目标片段。
- **Span Extraction**：把答案看作一个连续的文本片段，通过预测起止位置，或给候选片段打分来完成抽取。

**RoBERTa 负责生成上下文表示，BIO / Span 是抽取层面的方案。** 

它们不是三个互相竞争的「模型」。BIO 和 Span 也不是必须依次经过的两个步骤，而是可以采用的不同抽取方式。

这里的「理解文本」只能算一种简化说法。编码器只得到上下文表示。

## 找到一个词，不代表就是答案

例子：

> 张三原计划去北京，但后来取消了行程，最终去了上海。

> 问题：张三**实际前往**的城市是什么？

答案是「上海」。但是「北京」也确实出现在原文中，而且它同样是城市名。

这个例子让我把信息抽取拆成了两个不同的问题：

1. **找得到吗？** 能不能在文本中发现「北京」「上海」这样的候选片段？
2. **选得对吗？** 能不能结合问题中的「实际前往」，判断哪个候选真正满足条件？

如果只解决第一个问题，模型可能会把两个城市都输出。

对这个问题来说，「上海」是正例，「北京」则是负例——不是因为北京不是城市，而是因为它不满足这次抽取的条件。

模型可以通过简单的训练找出可能是正确答案的候选词。但当情况变得复杂、语义需要受到约束时，模型就可能会在候选词里选出并不正确的答案。

## 模型究竟怎样从正负例中学习？

以一个简化的二分类候选打分器为例：模型先给候选一个原始分数，叫 **logit**。它不是概率，可以小于 0，也可以大于 1。经过 sigmoid，可以转换成 0 到 1 之间的数，用来表示模型对候选为正例的倾向。

训练时，我们希望「上海」的分数更高，「北京」的分数更低。

Loss 用来衡量预测和训练标签之间的差距；接下来通过反向传播计算梯度，再由优化器更新参数。

我现在记住的一次训练更新流程是：

> `前向计算 → 计算 Loss → 反向传播 → 优化器更新参数`

这里还要区分**训练**和**推理**：Loss 用于指导训练，而推理时通常要把分数转换成最终预测，例如用阈值决定保留哪些候选。

阈值调高，可能减少误报，也可能漏掉正确答案；不能脱离验证集随便判断哪个好。

指标结果Precision0.3333Recall0.6476Micro-F10.4401

现在至少能更直观地看懂这三个数字了：模型找回了部分标准答案，但输出中也混入了不少错误答案。

不过，**低 Precision 并不能直接证明模型「不理解复杂语义约束」**。错误也可能来自候选边界、抽取类型、阈值或其他因素。要知道它究竟错在哪里，下一步还得把 FP 分类，检查具体文本和问题，再设计有针对性的对照实验。

这也对应了我目前对研究问题的理解：比赛要做的是复杂约束属性抽取；更长期的方向，则是让系统从上下文里识别出满足条件、值得信任的信息，再决定能不能写入。把候选找出来只是前半步，正确判断条件才是更难的部分之一。

## 6. 目前的理解边界，以及接下来学什么

这一阶段学过的知识，大致可以串成下面这条线：

`序列标注 → BIO / Span → 候选生成与判断 → 正负例 → Logit / Loss → 参数更新 → 阈值 → TP / FP / FN → Precision / Recall / F1`

现在让我再解释这些概念，至少有了一条基本的思路。但「能听懂」和「能独立设计、训练、诊断模型」显然还有很大距离，我也不打算把这篇笔记包装成已经掌握信息抽取。
